# 0006. Rules for the README analysis of the graph

- Status: accepted
- Date: 2026-11-09
- Deciders: @antunderwood
- Kind: scientific

## Context

Spec #34 regenerates the README's name-similarity assessment from a release graph. The existing script and the README disagree, and the script has defects found in tickets #35 and #37. Evidence from the 2026-11-09 graph (15,859 nodes): the only node named `blaPAO` is a ResFinder entry that is the best ResFinder match of every one of the 1,349 CARD and NCBI PDC alleles (a family representative, so name comparison with it is meaningless); the remaining blaPDC rows are CARD against NCBI allele pairs (1,351 rows, 107 of the 3,407 low-name-similarity rows at identity 0.95 or higher) whose low similarity reflects different alleles (for example NCBI `blaPDC-717` and CARD `PDC-552` at identity 0.997), not naming errors. NCBI is the naming authority for the blaPDC alleles.

## Options considered

1. Skip rule: only `blaPAO` (the code); `blaPAO` and `blaPDC` (the README); nothing skipped
2. `bla` removal: leading prefix only (the README); anywhere in the name (the code)
3. Allele-free threshold: from its own regression; from the full-name regression (the code)
4. Appendix summaries and `docs/data` examples: refresh both; appendices only; leave as historical
5. Terminal screenshots: PNG with the SVG beside it; SVG only

## Decision

1. Skip only matches involving the node named exactly `blaPAO`; keep every blaPDC allele pair. The number of skipped matches is written to `docs/statistics.json` and the README. The README sentence about blaPDC is corrected.
2. `clean_name` removes `bla` only as a leading prefix (fixes `cblA` becoming `c`; 6 names affected).
3. The allele-free analysis uses its own regression for both fit and threshold. Both predicted values are reported and labelled.
4. The appendix summaries and the `docs/data` example outputs are refreshed, generated by script from the same statistics file and from `chamredb query` on the release graph.
5. Screenshots are PNG in the README with the SVG committed beside each. *Amended 2026-11-10 at the maintainer's request:* the README embeds the SVG (the real emoji, drawn by the reader's browser); the PNG, which has plain symbols instead of the emoji, stays beside it.

## Consequences

The README numbers change with the graph and with decisions 2 and 3; each is shown beside the old value in the pull request. Decisions 2 and 3 are implemented in the statistics ticket (#38) with their own tests; the strict expected failure for `bla` in `analysis/tests/test_cleaning.py` flips to an ordinary test there. Figures and screenshots follow in #39 to #43.
